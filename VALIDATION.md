# Проверка JimmMac

## Версия 0.13.0 — 3 ноября 2026

На доступном MacBook с OS X 10.9.5 прошли по **156 проверок протокола, хранения,
экспорта, обновлений и Security** на NSURLSession и принудительном NSURLConnection,
**30 проверок HTTP** и **327 проверок UI** — всего **669**. Конечное приложение
собрано Xcode 5.1.1 / SDK 10.9, target 10.8, Intel x86_64. Реальный запуск на
10.8 и 10.10–10.13 по-прежнему не заявляется.

- SQLite заменяет полную перезапись JSON. Миграция проходит транзакцией;
  исходный JSON остаётся неизменным. Повреждённый JSON не затирается.
- На том же Mac 10 000 отдельных вставок с WAL / synchronous=FULL заняли около
  3,6 с; чтение страницы и Unicode-поиск — около 0,12 с. Это измерение фикстуры,
  а не гарантия для всех дисков. Страница ограничена 200 сообщениями.
- Непрочитанное состояние сохраняется одним INSERT с сообщением; повторы не
  увеличивают счётчик. Проверены восстановление, первое непрочитанное, прочтение
  и отсутствие преждевременного сброса при открытии старой страницы.
- Исходящее сообщение сохраняется до запроса. После прерванной отправки остаётся
  «Подтверждение не получено», без автоповтора. Подтверждение объединяет локальную
  запись с уже полученным echo. Искусственный отказ записи подтверждения проверяет
  rollback без потери исходного текста. Ручной повтор сохраняет независимый черновик.
- Избранные идут первыми и сохраняются по UIN аккаунта. Проверены сочетания фильтров,
  пустые состояния, размещение кнопок и флажков в окне 860 × 560.
- Смайлики используют NSTextAttachment с исходным текстом в атрибуте. Проверены
  отключение и обычный Cmd+C с восстановлением `:)` вместо символа вложения.
  Тест сохраняет и восстанавливает буфер обмена только в памяти.
- Экспорт TXT/HTML работает по отдельному снимку SQLite и пишет временный соседний
  файл с атомарной заменой результата. Проверены полный текст, переносы строк,
  экранирование HTML, права 0600 и отказ записи.
- Автоматическая проверка обновлений запускается после старта и затем раз в 6 ч;
  доступное обновление показывается один раз, только когда главное окно готово.
  Проверены отложенное окно, отсутствие повторных показов, текущая версия без
  всплывающего окна, тихий сетевой сбой с задержкой и отключение через меню.
- Cmd+Q дожидается фонового экспорта, не блокируя UI. Тест удерживает очередь
  экспорта семафором и проверяет, что завершение происходит только после записи.
- Проверка обновлений протестирована через фиктивные HTTP-ответы обоих транспортов:
  числовые версии, неверные данные, HTTP 503, запрет постороннего URL, отсутствие
  токена, cookies и query аккаунта. Живой запрос GitHub на Mavericks успешно вернул
  опубликованную 0.12.0 как через NSURLSession, так и через NSURLConnection.
- Mavericks не доверял современной цепочке GitHub. Добавлены официальные публичные
  корни Sectigo E46 и USERTrust ECC только для api.github.com. Они не устанавливаются
  в Keychain. Security продолжает проверять hostname, срок и подписи; тесты отвергают
  другой host, просроченный leaf и попытку подставить root вместо серверного сертификата.
  Функция SecTrustSetNetworkFetchAllowed появилась в 10.9 и вызывается через dlsym
  только при наличии; это не отключает проверку на 10.8. Обычное доверие Jimm.online
  и аватаров не менялось.

Обновлённое приложение 0.13.0 build 20 установлено атомарной заменой в
`/Applications/JimmMac.app` и каноническую папку сборки. Работающий процесс не
завершался; обычный повторный запуск производится из Finder. SHA-256 установленного
executable совпал с полученным bundle: `e2f69949332deee7b633364896a9f256ffb9286c298f33e2904c13b978d5c1f8`.
Снимки UI-daily-history и UI-daily-send-state отрисованы и просмотрены на Mavericks.

Все тесты истории, профилей, сообщений и снимки используют вымышленные данные.
Реальная переписка, пароль и сохранённые токены пользователя не читались.
Пользователь проверил экспорт и окно обновлений на настоящем аккаунте.
При первом запуске сервер отказал предыдущему сохранённому входу; после ручного
входа пользователь повторно запустил приложение и подтвердил автовход.
Точная причина отказа старого токена не установлена: прежний клиент сбрасывал
журнал при новой попытке. В 0.13 диагностические метаданные сохраняются между
попытками, а отказ токена объясняется отдельно от неверного пароля.

## Версия 0.12.0 — 2 ноября 2026

На OS X 10.9.5 прошли по 122 проверки протокола, хранения и Security API
для двух сетевых путей, 30 проверок HTTP и 292 проверки UI — всего 566.
Проверки выполнялись Xcode 6.2; конечное приложение собрано Xcode 5.1.1 / SDK 10.9
с target 10.8 без предупреждений. Mach-O x86_64 и minimum 10.8 проверены otool;
nm подтверждает weak external для NSURLSession и NSURLSessionConfiguration.
Изменения охватывают клавиатуру, оформление и установочный DMG.
Все 19 HTTPS-маршрутов проверены с фиктивной недействительной сессией:
сервер вернул ожидаемые API 401, проверка TLS-сертификата включена.

- Убрано дублирование аккаунта: имя/UIN показываются только в заголовке,
  состояние соединения — только внизу. Проверены пустое имя и обрыв связи.
- Исправлены потеря фокуса при навигации стрелками и перенос undo/redo между
  переписками. После подтверждения отправки нельзя отменить её в поле ввода.
- Настоящие NSEvent проверяют правку в сообщении, входе, защищённом поле,
  истории, редакторе профиля и модальных UIN-диалогах.
- Русские кнопки «Отмена» явно получают Escape: на англоязычном Mavericks
  AppKit не распознавал их как Cancel. Проверено фактическое закрытие обоих
  UIN-диалогов, добавлен срок ожидания модальных тестов.
- Cmd+L ищет в списке, Shift+Cmd+L выходит из аккаунта. Enter в списке
  переводит в сообщение, Enter в UIN — к паролю. Cmd+S сохраняет профиль.
- Нелатинские Command-события известных меню переводятся через системную
  ASCII-совместимую раскладку Carbon TIS/UCKeyTranslate. Жёсткого US-сопоставления
  keyCode нет; валидация и выполнение команд остаются у AppKit.
- Новое входящее сообщение сохраняет выделенный для копирования текст истории.
- Зелёный заголовок ICQ сочетается с серебристой основой AppKit. Добавлены
  отдельные окна «О программе» и справки по клавиатуре.
- Ссылка в «Справке» и «О программе» ведёт на проверенную публичную страницу
  https://github.com/MiChiRose/telegraphica. Автоматический тест перехватывает
  открытие URL до NSWorkspace и не запускает браузер.
- Новый DMG: HFS+ / UDZO, фон 1×/2×, цветок ICQ, Applications, стрелка и инструкция.
  Оформление Finder записывается через dmgbuild без AppleScript и изменения
  настроек Finder пользователя. Учтены заголовок и строка пути Mavericks.

Поддержка расширена до одного приложения OS X 10.8–macOS 10.13 / x86_64.
На 10.8 выбирается NSURLConnection, на 10.9+ сохраняется NSURLSession. Тесты
обоих путей включают буферизацию частями, ограничения Content-Length и тела,
таймаут, отмену ровно один раз, запрет новых задач после invalidate и redirects.
Оба пути прошли 19 реальных HTTPS-запросов с недействительной сессией без
ослабления проверки сертификатов. Identifier уведомления вызывается только при
наличии метода на конкретном объекте. Отдельно проверены coalescing и clear-peer
без этого свойства. Пользователь подтвердил, что доступны только Mavericks:
реальное исполнение на 10.8 и 10.13 не заявляется.

Итоговый DMG прошёл hdiutil verify на современном Mac и Mavericks, суммы
SHA-256 совпали после переноса. Образ HFS+ смонтировался обычным двойным щелчком
Finder; осмотр через «Общий экран» подтвердил весь фон и подписи без обрезания,
включая нижнюю строку диапазона и включённую в системе строку пути.
Ссылка Applications ведёт в /Applications. После первоначальной проверки копирования
через ссылку пользователь вручную проверил перетаскивание и запуск из «Программ».
Пользователь подтвердил автовход, отправку !help боту 11114 и получение ответа без
ручного обновления: «да, всё окей». Содержимое переписки, токен и пароль не читались.
SHA-256 установленного файла сравнивается с конечным bundle.

Все автоматические сообщения и снимки используют фиктивные данные.
Буфер обмена тестов Cmd+C/X/V сохраняется только в памяти и восстанавливается;
его содержимое не попадает в журналы и артефакты.

## История проверки 0.11.0 — 30 октября 2026

## Оформление 0.11.0

На OS X 10.9.5 / Xcode 6.2 прошли **121 проверка протокола, хранения и Security API**
и **241 проверка интерфейса**. Сборка Intel x86_64 / SDK 10.10 / target 10.9
без предупреждений. Сетевые маршруты и способ сохранения входа не менялись.

Список получил согласованные отступы, время последнего сообщения и подсказку
с полной датой. Непрочитанное отмечается жирным именем и отдельным значком,
после 99 — «99+». Полное число (в тесте 500) доступно в tooltip и нативной
NSTextFieldCell Accessibility, независимо от компактной отрисовки.
Черновик остаётся явно подписанным и имеет дополнительное цветовое отличие.
Время резервирует ширину по cellSize родной ячейки AppKit вместе с её отступами.

Для выделения используются отдельные фоны и цвета текста с фокусом и без него.
Проверен контраст не ниже 4.5:1 для имени и превью в обоих состояниях, в том числе
для черновика. У ячеек проверены длинное имя, «Вчера», 500 непрочитанных,
отсутствие пересечений, полный tooltip и очистка прежнего вида при повторном
использовании. Фон списка ровный; нижняя панель расширяется только при наличии
обратной связи контакт-листа.

История разделена по дням: один центрированный заголовок даты, имя и короткое
время у сообщения, полный момент отправки по наведению. Добавлены межстрочные
отступы. Даты масштабируются с размером текста, включая настройку 28 пунктов.
Дата не получает JMMessageID: контекстные действия относятся только к сообщению.
Сохранились ссылки, диапазоны поиска и цитирования, прокрутка старой истории,
автоматический приём и переход к новым сообщениям — проверены прежней UI-серией.

Пустое окно показывает цветок ICQ, пояснение и кнопку разговора по UIN.
Пустая выбранная переписка предлагает написать первой. Подсказка «Сообщение…»
рисуется отдельно от string поля и не попадает в отправку или сохранённый черновик.
Элементы пустого окна проверены по границам в минимальном размере 860 × 560;
проверялись также стандартный и большой размеры и длинные имена.

Снимки UI-chat-polished.png, UI-peer-empty.png, UI-empty.png и снимки большого
шрифта отрисованы непосредственно AppKit на Mavericks и просмотрены. Для них
использовались только фиктивные контакты и история. Живой аккаунт не читался.
После установки пользователь открыл версию 0.11.0 из Finder и подтвердил,
что список переписок, разделители дат и поле сообщения видны полностью
и выглядят красиво при его размере окна. Доступ к Связке ключей сохраняется
при обычном запуске из Finder.

## Сохранённый вход 0.10.0

На Mavericks / Xcode 6.2 прошла **121 проверка протокола, хранения и Security API**.
Результат проверки интерфейса: **222 проверки**. Сборка без предупреждений.

Добавлен флажок «Запомнить меня». clientLogin запрашивает tokenType=longterm;
сохраняется только выданный токен с expiresAt и UIN после успешного startSession.
Пароль не сохраняется. Повторный запуск читает только запись сервиса JimmMac
для выбранного UIN, проверяет её срок и GET /auth/getInfo, сверяет loginId,
затем открывает новую сессию без clientLogin. При временном сбое проверка
повторяется; отмена возвращает ручной вход. Уведомление другого аккаунта
не запускает сохранённый UIN вместо требуемого.

JMLoginStore использует Security.framework и точный query: generic-password,
service online.jimm.mavericks.login-token и account UIN. Реальные SecItemAdd,
SecItemCopyMatching, SecItemUpdate и SecItemDelete проверены на MacBook в отдельной
временной Связке ключей с фиктивными значениями. Проверены создание, чтение,
обновление, отдельные UIN, срок действия, удаление и запрет широкого удаления
с пустым UIN. Временная Связка удалена; login.keychain пользователя не читалась
и не менялась этими автоматическими проверками.

Все операции Связки выполняются в отдельной последовательной очереди.
Cmd+Q ждёт её завершения через штатный NSTerminateLater, оставляя UI доступным.
Запись при успешном входе завершается до окончательного выхода; сохранённый
вход остаётся для следующего запуска. Явный выход из аккаунта очищает указатель
автовхода и удаляет запись этого UIN после ранее поставленного сохранения.

UI-проверки используют отдельный NSUserDefaults и подменённое хранилище.
Проверены флажок, longterm/shortterm, очистка поля пароля, отсутствие секретов
в preferences, сохранение токена и автовход без повторного ввода пароля,
отмена без забывания записи, истечение и отказ сервера, недоступная Связка,
ошибка сохранения и удаление. Позднее чтение после отмены и позднее сохранение
после выхода не возвращают прежний вход. Новые кнопки и флажок проверены
по границам окон; снимки входа отрисованы на Mavericks и просмотрены.

Контракт сверён с [Jimm.online](https://jimm.online/developers),
модель поиска записей — с [Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains).
В первом пользовательском запуске 0.10.0 возникла ошибка «Вход не сохранён,
Связка ключей недоступна». Клиент был открыт через SSH-команду open.
Отдельный диагностический процесс, не читающий ни одной записи, показал
sessionHasGraphicAccess=0 и заблокированную Связку как при запуске из SSH,
так и через open из SSH. Проверялись только флаги и коды состояния.
Штатные launchctl asuser/bsexec без прав администратора не смогли переключить
контекст; привилегии и настройки безопасности не менялись.

Пользователь завершил JimmMac через Cmd+Q, открыл его из Finder и вошёл
с «Запомнить меня»: ошибка исчезла. Затем снова завершил приложение через
Cmd+Q и открыл из Finder; подтвердил автоматическое подключение без пароля.
Сохранение и автовход в настоящем аккаунте подтверждены. Инструкция установки
уточнена: удалённая сборка допустима, интерактивный запуск выполняется на Mac
из Finder. Пароли и токены не читались средствами диагностики.

## Переписка, цитаты и черновики 0.9.0

На MacBook с OS X 10.9.5 / Xcode 6.2 прошли **104 проверки протокола и хранения**
и **205 проверок интерфейса**. Финальная сборка — Intel x86_64, deployment target
10.9, без предупреждений компилятора. Новых серверных маршрутов в этом выпуске нет.

Черновики сохраняются в отдельный drafts.json для каждого аккаунта. Запись
атомарная, в последовательной фоновой очереди после паузы ввода; перед выходом
или сменой аккаунта очередь завершается. Проверены восстановление после создания
нового хранилища, независимость собеседников и аккаунтов, удаление пустого или
успешно отправленного текста, права 0600 и отказ перезаписывать повреждённый файл.
Старый результат фоновой записи не меняет состояние нового аккаунта или свежего
черновика. Ошибка видна в окне; отказ от потери черновиков отменяет выход.

В контекстное меню сообщения добавлены копирование целого текста и ответ цитатой.
Проверены сохранность набранного ответа, многострочный текст и пустые строки,
ссылки и специальные символы, отсутствие автоматической отправки, сохранение
цитаты на диск и сохранение стандартных пунктов NSTextView. Пустое место между
сообщениями не даёт чужого действия. Старое меню не работает после выбора другой
переписки или выхода из аккаунта. Тест копирования подменяет запись в pasteboard
и не меняет пользовательский буфер обмена.

Проверены Enter, Shift+Enter и Cmd+Enter через настоящие NSEvent и цикл событий
этого тестового приложения, с активацией окна и штатной валидацией меню AppKit.
Cmd+Enter не отправляет сообщение из другого окна. Режим отправки сохраняется
отдельно от настроек шрифта. Незавершённая композиция метода ввода не отправляется.
Длинный текст остаётся доступным для редактирования, а лимит 4000 байт UTF-8
и текущий размер показываются до отправки. Окно настроек просмотрено с шрифтом
13 и 28 пунктов: образец, переключатель режима и кнопки помещаются целиком.

При ожидании ответа сервера проверены дополнительный ввод, полная замена текста,
отсутствие повторной отправки по второму Enter, подтверждение после смены
собеседника, сохранение нового черновика и восстановление обоих текстов при таймауте.
Неподтверждённый текст сохраняется на диск вместе с заменившим его черновиком;
после подтверждения остаётся только новый. Позднее подтверждение после выхода
не возвращает прежнюю историю и не удаляет сохранённый черновик. Повторов по сети нет.

Все отправки в автоматических UI-проверках выполняются подменённым JMAPIClient:
настоящие сообщения собеседникам не отправлялись, личная переписка не читалась.

На 10.9.5 воспроизведена блокировка NSTextView в выбранном разговоре при потере
соединения. Теперь состояние сети управляет только кнопкой отправки; поле остаётся
редактируемым. Для отсутствующего адресата добавлена явная подсказка.

Исправлена также потеря черновика: прежний код сохранял живой изменяемый буфер
NSTextView. Теперь сохраняется копия строки, включая текст ожидающей отправки.

Проверка UI расширена и прошла на Mavericks: клавиатурные события внутри тестовых
окон действительно вводят текст онлайн и офлайн, черновик переживает переключение
собеседника, UIN вводится и фиксируется в настоящем модальном NSAlert.
Тесты не вводят текст в пользовательскую сессию и не отправляют реальных сообщений.
